## 3. MCP 服务器镜像（核心能力）

### 3.1 解析（`lib/config.mjs` + `lib/mcp.mjs`）

从 `config.toml` 提取 `[mcp_servers.<name>]`，归一化为：

```js
{ source: 'codex', name, type, command, args: [], env: {}, startupTimeoutSec }
```

- `type`：`stdio`（默认）| `sse` | `http`；缺失视为 `stdio`。
- `args`：支持 `["a", 'b']` 单双引号数组（复用 dsh-chat-import `parseTomlArray` 语义）。
- `env`：支持 `{ KEY = "value" }` 内联表；含 `${VAR}` 的值原样保留（DSH 侧展开）。
- `startup_timeout_sec`：数值保留。

### 3.2 运行时服务器排除规则（重要）

以下服务器**默认排除**并报告（`excludeRuntime:true` 参数可关）：

- 名称匹配：`node_repl`、`computer_use`、`browser`、`chrome`；
- 命令路径含：`Codex\runtimes`、`openai-bundled`、`codex-computer-use`、`node_repl.exe`；
- `env` 中含 `CODEX_CLI_PATH` 或 `SKY_CUA_NATIVE_PIPE*` 的服务器。

### 3.3 密钥策略（对每个服务器逐字段判定）

| 字段 | 判定 | 处理 |
| --- | --- | --- |
| `args` / `env` 中匹配 `(?i)pass(word)?\|token\|secret\|key\|bearer` | 敏感 | **默认按原样迁移**（用户明示需求，迁移后直接可用）；`maskSecrets:true` 时替换为 `****`；无论哪种模式，报告都给出敏感值计数 |
| `env.PATH` 含 `${PATH}` | 透传 | 原样保留 |
| 其他 | 普通 | 原样保留 |

> ⚠️ 原样迁移意味着镜像片段含真实密钥：请勿把 `mcp-mirror.cordis.yml` 等产物提交到公开仓库（见 [09-安全边界](09-安全边界.md)）。

### 3.3b 选择性迁移（include / exclude）

- `include: [name]` 只迁移列出的服务器（精确名）；缺省 = 全部。
- `exclude: [name]` 排除列出的服务器；支持 `*` 前缀通配（如 `exclude: ["kingbase-*"]` 排除全部金仓库）。
- 运行时服务器排除规则（§3.2）始终优先。
- UI 中每个服务器有勾选框，默认全选。

### 3.3c 本地工具目录随迁（mcp-toolbox 等）

- 检测：服务器 `command/args/env` 中引用 `~/.codex/tools/<name>` 路径 → 视为本地工具（如 `mcp-toolbox` 的 `toolbox.exe` + `tools.yaml`）。
- 迁移：`migrateTools`（默认 true）时把整个工具目录复制到 `$DSH_HOME/codex2dsh/tools/<name>`；目标已存在则跳过（幂等）。
- 路径重写：镜像片段中 `command/args/env` 里的 Codex 侧路径**同步改写**为目标路径，保证镜像开箱即用。
- 报告类别：`kind: "tool"`。

### 3.4 输出格式（`mcp-mirror.cordis.yml`）

生成**可人工审阅合并**的 DSH MCP client 配置片段。DSH 生态的 MCP client 插件（`dsh-mcp-client`）以 Cordis 组合条目启用，因此镜像文件顶层结构与 `cordis.patch.yml` 兼容：

```yaml
# codex2dsh 生成的 MCP 镜像（人工审阅后合并进 profile 的 cordis.patch.yml / cordis.yml）
# 来源: C:\Users\<user>\.codex\config.toml · 幂等键: sha256(config.toml)
# ⚠️ 默认密钥原样迁移；本文件含真实凭据，请勿提交公开仓库
- insert:
    - id: dsh-mcp-client
      name: dsh-mcp-client
      config:
        servers:
          google-mcp-toolbox:
            type: stdio
            command: 'C:\Users\<user>\.dsh\codex2dsh\tools\mcp-toolbox\toolbox.exe'   # ← 工具目录已随迁并重写路径
            args: ["--config", 'C:\...\tools.yaml', "--stdio", "--disable-reload"]
            startupTimeoutSec: 120
          kingbase-gchgz-dsj-dev:
            type: stdio
            command: "npx"
            args: ["universal-db-mcp", "--permission-mode", "readwrite",
                   "--type", "kingbase", "--host", "192.168.10.99", "--port", "54322",
                   "--user", "system", "--password", "<原样保留>", "--database", "dsj"]   # ← 默认原样迁移
            startupTimeoutSec: 120
```

> 契约说明：dsh-community-market 的安装器对 "DSH bundle patch" 的校验是"安装包内存在且不越界"，`dsh-mcp-client` 的服务器配置形态以该插件发布文档为准；本规范把"服务器配置块"作为**独立 YAML 片段**生成，合并时可整体放入 `config:` 下，兼容性由 fixture 单测锁定。

### 3.5 幂等

- 目标文件已存在且内容相同 → `skipped`；
- 已存在但内容不同 → 默认**不覆盖**（提示 `--force` / `force:true`），防止覆盖人工修改过的合并结果。

## 4. 技能转换（核心能力）

### 4.1 判定哪些技能可迁移

| 条件 | 处理 |
| --- | --- |
| 目录名以 `.` 开头（`.system` 等） | 跳过（运行时） |
| 目录名含 `codex-primary-runtime` / `openai-bundled` / marketplace 分发标记 | 跳过（报告原因） |
| `SKILL.md` 缺失 | 报告 `invalid`（可选 `--fix-frontmatter` 补全，见 4.4） |
| 未选中（`include` / `exclude`） | 跳过（`exclude` 支持 `*` 前缀通配，如 `exclude: ["ccpanes-*"]`） |
| 其余（用户/第三方安装） | ✅ 迁移 |

**选择性迁移**：`include`/`exclude` 参数（精确名 + `*` 前缀通配）过滤候选技能；UI 中每个技能有勾选框，默认全选，支持「按前缀排除」（输入逗号分隔的前缀批量取消勾选，如 `ccpanes-`）。

### 4.2 SKILL.md 转换规则

```markdown
# Codex 源（frontmatter: name/description）
---
name: find-skills
description: 检索已安装技能并给出使用方法。
---

# DSH 目标
---
name: find-skills
description: 检索已安装技能并给出使用方法。   # 保留原文
kind: dsh                                    # ★ 标记已适配 DSH
source: codex                                # ★ 来源标记（供审计/幂等）
---
（正文原样保留，不做摘要）
```

- **正文原样保留**（Codex 与 DSH 的技能正文均为 Markdown 指令文本，可直接复用）；
- `kind: dsh` 标记用于：已带该标记的技能**不重复导入**（幂等判定）；`scripts/` 目录整体复制；
- 冲突：`$DSH_AGENTS_HOME/skills/` 已存在同名 → 新目标加 `-codex` 后缀（`find-skills-codex`），报告消歧；
- 内容完全相同 → `skipped`。

### 4.3 脚本目录

`SKILL.md` 引用的 `scripts/*` 一并复制；若脚本含 shebang/路径，报告差异（如 `codex exec` 相关脚本提示人工适配）。

### 4.4 缺 frontmatter 的补全

技能目录存在但 `SKILL.md` 缺 `name/description`（罕见）：`--fix-frontmatter` 时用目录名补 `name`、用首段文本生成 `description`，并在报告标注 `auto-filled`。

> **目标位置说明（2026-08 修正）**：DSH 的「用户全局指令」只有唯一位置 ——
> `$DSH_HOME/AGENTS.md`（`@deepseek-ai/dsh-agent-instructions` 的

> CLAUDE.local.md`）。`$DSH_AGENTS_HOME` 下的目录（如 `~/.agents/instructions/`）
> **不参与指令发现**——旧版迁移写 `~/.agents/instructions/global.md` 导致
> 全局规则不生效，0.1.1 已修正为写 `$DSH_HOME/AGENTS.md`（instructions.md
> 合并进同一文件，分节保留）。

| 源 | 目标 | 规则 |
| --- | --- | --- |
| `~/.codex/AGENTS.md` | `$DSH_HOME/AGENTS.md` | 原文完整保留；文件头追加来源注释块（`<!-- codex2dsh: 来源 ... -->`）；**自动适配 Codex 专属引用**（见下） |
| `~/.codex/instructions.md`（若存在） | 合并进 `$DSH_HOME/AGENTS.md`（分节） | 与 AGENTS.md 合并为单一全局指令文件，保证 DSH 一次加载全部全局规则 |
| 项目级 `AGENTS.md`（扫描 Codex 项目信任列表） | 报告 + 生成项目级指令挂载建议 | 不自动写盘（R4）；项目目录下的 AGENTS.md/CLAUDE.md 由 DSH 自动发现注入 |

**Codex → DSH 引用适配**（`adaptCodexReferences`，迁移质量核心——规则不能简单复制）：

| 引用类型 | 处理 |
| --- | --- |
| 本地工具绝对路径（`<codexHome>/tools/<name>/...`，含 `~/.codex/tools/...` 形态，反斜杠/正斜杠兼容） | 改写为 `$DSH_HOME/codex2dsh/tools/<name>/...`（migrateTools 随迁目录；保留原文风格），记录改写点 |
| MCP 工具前缀 `mcp__<server>__` | 命名规则与 DSH 一致（dsh-mcp-client 同为 `mcp__<serverName>__<rawName>`）不改前缀本身；服务器名下划线形态（如 `mcp__google_mcp_toolbox__` 实际名 `google-mcp-toolbox`）自动归一改写 |
| `<server> MCP` 字样引用（含反引号/大小写） | 对照 DSH 侧已配置服务器（mirror 解析），未配置的逐条警告（不自动删正文，由用户决策：补配置或移除引用） |
| 其余 Codex 环境专属能力（如运行时 node_repl） | 不在 mirror 配置中时按未配置服务器警告 |

## 8. 会话委托

`migrate_codex_sessions` 行为：

1. 只读统计 `sessions/YYYY/MM/DD/rollout-*.jsonl`（数量、总行数、时间范围）；
2. 检测 `import_chat` 工具可用性（`ctx.tools` 中查找）：
   - 可用 → 直接委托（`preview` 时调用其 preview 语义），返回其导入结果摘要；
   - 不可用 → 返回安装指引（`dsh plugin --profile <p> add dsh-chat-import`）。
3. 台账记录委托结果（会话数、来源指纹）。

### 8.1 标题回填（session/title 事件）

**问题**：`import_chat`（dsh-chat-import）的 codex 转换器只回填 `out.title`，
从不写 `session/title` 事件；DSH 界面标题取「最后一条 session/title 事件」，
缺失时回退首条 `user/message`。而 Codex rollout 的首条 user 消息几乎总是
harness 注入（`<environment_context>` / `# AGENTS.md instructions` /
`<agents-instructions>`），导致导入会话全部显示成工作区/路径类标题。

**回填规则**（`codex2dsh_fix_titles` 工具 / 面板「修复标题」/ 导入后自动执行）：

1. 只处理带 `session/imported`（`data.tool === 'codex'`）标记的会话；
2. 已有 `session/title` 事件（含用户手动改名）**跳过**——只补不覆盖；
3. 标题源（按优先级）：
   a. `~/.codex/session_index.jsonl` 的 `thread_name`（Codex 官方线程标题，
      同 id 多条取 `updated_at` 最新；空名跳过）；
   b. rollout 文件的「首条真实提问」：只认 `response_item/message` role=user，
      跳过 `<` 开头块与 AGENTS.md/CLAUDE.md 指令注入（`# AGENTS.md instructions` /
      `<INSTRUCTIONS>`），归一化（去空白、>80 字符截断加省略号）；
   c. 两者皆无 → `skipped(no-title-source)`。
4. 写回：`sessionPersistence.append` 追加 `session/title` 事件
   （`seq` = 日志事件数、`data: { title, messageSeqs: [], source: { kind: 'user' } }`，
   与 DSH `session-title` 服务的 `rename()` 形状一致），写后刷新
   `sessionProjectionCache.coldSnapshot` 让界面立即显示；
   ⚠ **禁止给 `session/title` 附加 `surfaceOp`**：DSH 宿主只允许
   `user/message` / `assistant/message` / `tool/result` 携带 surfaceOp，非
   surface 事件携带 surfaceOp 会让整份日志打开时校验失败
   （`SessionPersistenceCorruptionError`）。0.1.1 早期版本误加 surfaceOp 导致
   已回填会话无法打开，用 `codex2dsh repair-titles --apply`（CLI）清除坏事件
   后重启 DSH 再回填即可恢复；
5. 安全性：跳过 live 会话；CLI `titles` 子命令只读预览不写盘（直写日志文件
   会与宿主写游标并发冲突，写盘必须在 DSH 宿主内执行）；`repair-titles`
   是唯一的直改日志入口（截断末帧坏标题事件，需在宿主外执行，修复后重启）。

### 8.2 工作区归组修复（非工作区会话统一归组）

**问题**：DSH 的 workspace 语义 = 会话 header.cwd 的 realpath（按目录分组、
启动时 reconcile）。Codex 的「非工作区会话」（projectless）cwd 是
`Documents\Codex\<日期>\<主题>` 这类一次性目录，迁移后**每个会话一个独立
workspace**；又因 `C:` 前缀字母序排前，侧边栏出现「非工作区会话反而在最
上面、工作区会话在最下面」的乱序。

**修复规则**（`codex2dsh_regroup_sessions` 工具 / 面板「整理工作区」/
CLI `codex2dsh regroup`）：

1. 非工作区判定（权威优先）：
   a. `~/.codex/.codex-global-state.json` 的 `projectless-thread-ids`
      （Codex 官方标记的 projectless 线程 id，与 rollout sourceId 对齐）；
   b. 兜底：cwd 位于 `thread-workspace-root-hints` 众数根（如
      `C:\Users\ichin\Documents\Codex`）之下（旧线程未进列表的情况）。
   其余会话一律不动：cwd 在任一项目 `rootPaths` 下 = 工作区会话；未登记
   目录保守跳过（避免误伤真实工作目录）。
2. 归组：把非工作区会话的 **header.cwd 统一改写**为目标目录（默认 = hints
   众数根；可 `--dir` 覆盖），并把会话日志目录**物理移动到**新 projectKey
   目录（DSH 按 projectKey 组织物理目录）。header 是日志第一帧（zstd 首帧 /
   明文首行），重写后其余事件帧原样保留、seq 不变。
3. 排序：不动——DSH 启动 reconcile 按组内会话时间排序，归组正确后非工作区
   会话集中在尾部，与 Codex 列表顺序一致。
4. 安全性：只处理带 `session/imported`（tool='codex'）标记的会话；live 会话
   跳过；幂等（已归组 = header.cwd 已等于目标目录 → 跳过）；默认 dry-run；
   **执行后需重启 DSH** 让 workspaceRegistry 重建成组（运行中的分组索引仍按
   旧 cwd）；委托导入只报告非工作区会话数，不自动移动（避免与宿主写游标冲突）。

## 9. 不迁移清单（明示跳过）

| 项 | 原因 | 报告动作 |
| --- | --- | --- |
| `auth.json`、`.codex-global-state.json` | 凭据/设备状态 | `skipped(secret)` |
| `chrome-native-hosts*.json` | 本地桥接含密钥 | `skipped(secret)` |
| `[desktop]` 主题/字体/头像 | DSH 皮肤体系不同 | `skipped(not-applicable)` |
| marketplace/插件本体 | 许可证与分发绑定 | `skipped(not-applicable)` + 功能等价建议 |
| `history.jsonl`、运行时 sqlite（goals/queue/state/thread_history） | 运行时状态，无迁移价值 | `skipped(not-applicable)` |
| 运行时 MCP（node_repl 等） | DSH 自带等价能力 | `skipped(runtime)` |
