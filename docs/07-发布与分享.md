# 07 · 发布与分享

> 状态：**基线文档**（基于 dshmarket 1.17.1 与 dsh-community-market 契约实测归纳） · 关联：[06-测试与验收](06-测试与验收.md) · [09-安全边界](09-安全边界.md)

目标：让 `codex2dsh` 被"更多人"发现、一键安装、可信。分享链路有四层，按投入产出排序。

## 1. 第一层：npm 发布（一切的基础）

```bash
# 前置：测试全绿（见 06-测试与验收）
npm login
npm version 0.1.0 -m "chore(release): v0.1.0"
git push --follow-tags
npm publish --access public
```

**包体要求**（市场安装器硬性校验，缺一不可）：

- `files` 中必须包含 `cordis.patch.yml` 且文件真实存在、不越界；
- **不得包含** `preinstall/install/postinstall/prepare` 生命周期脚本（市场直接拒绝）；
- 声明与 DSH 兼容的 peerDependencies（`@deepseek-ai/cordis ^4.0.1` 等）与 `engines.node >= 22.13`；
- 提供官方 tarball 与 SHA-512 integrity（npm 自动保证）。

## 2. 第二层：awesome-dsh-plugin.com 注册表收录（人工 PR）

DSH Desktop 内置市场的"发现"视图读取 **awesome-dsh-plugin.com** 的精选清单，条目字段（实测 `RegistryPlugin`）：

```jsonc
{
  "name": "codex2dsh",
  "owner": "<你的 GitHub 用户名>",
  "url": "https://github.com/<你的用户名>/codex2dsh",
  "category": "migration",
  "description": { "en": "...", "zh": "把 Codex 的 MCP/技能/全局配置/记忆迁移进 DSH" },
  "npm": "codex2dsh",
  "install": "dsh plugin --profile web add codex2dsh",
  "added": "2026-08-13"
}
```

收录方式：向 [awesome-dsh-plugin/awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 提交 PR（参考 dsh-chat-import 的收录记录：其 ROADMAP 列出了 8+ 个已收录渠道）。

## 3. 第三层：dsh-community-market 目录（DSH Desktop 市场页）

DSH Desktop 的市场页（Market）按 **catalog-provider-contract v1** 工作：

```
标准来源 manifest（静态 JSON，自述查询能力）
   └─ GET /v1/plugins ──► 标准适配器（standard-http）──► 标准化快照
合作方（1024Store / dshfind）──► 内置适配器（dsh-1024store.ts / dshfind.ts）
```

要点（来自契约文档与实现）：

- **市场无默认/兜底来源**：用户必须显式选择或添加来源；任何人可发布符合契约的来源（manifest URL），不需要合作批准；
- 来源 manifest 决定条目：`package`（npm 名）、`latestVersion`、`repository`、`category`、展示字段；
- **安装只认精确 npm 包**：拒绝 GitHub URL、版本范围、`latest`、prerelease、带生命周期脚本的包；安装前做 `preview`（官方 registry 复核 + 当前 profile 复核），确认后受管 `pnpm add`；
- 安装前 Desktop 对 profile 的 `package.json / pnpm-lock.yaml / pnpm-workspace.yaml` 做快照，失败回滚；重启后健康才提交；
- 因此我们的发布动作：**保证 npm 包质量**（§1 清单）+ 视需要向 1024Store / dshfind 提交收录申请（按其对外的收录流程）。

## 5. 版本管理与 CHANGELOG

- **SemVer**：`0.x` 阶段 minor 兼容破坏需在 README/CHANGELOG 标注；peer 版本策略（`@deepseek-ai/*` rc 系列）跟随生态基线（当前：cordis ^4.0.1 / dsh-tools ^0.1.0-rc.6）；
- **发布流程**：`npm version` 打 tag → push → `npm publish`；`CHANGELOG.md` 按 [Keep a Changelog](https://keepachangelog.com/) 维护，与 docs 状态行同步；
- **CI 门禁**：`prepublishOnly` 跑 `npm test && git diff --quiet && npm pack --dry-run`（参考生态做法），防脏发布。

## 6. 每次更新的发布流程（全链路同步，非首次发布）

> **原则**：一次更新 = 一个版本，四个触点同步（GitHub 仓库 / npm / 插件市场 / 本地 DSH），
> 发布前用 `codex2dsh verify` 确认迁移真实可用（不是"文件生成了"就算完成）。

### 6.1 代码与质量（完成功能后）

1. 修改代码并补测试：`npm test` 全绿（L1+L2）、L3 冒烟通过、`check:fixtures` 通过；
2. 版本号 bump：`npm version patch|minor`（或手改 `package.json` 的 `version`）；
3. `CHANGELOG.md` 记录本次变更（Keep a Changelog 格式，与 README 功能描述一致）。

### 6.2 GitHub 仓库触点

4. `README.md`：功能表 / CLI 示例 / FAQ 同步新功能；截图变化时更新 `assets/`
   并确认 raw URL 返回 200；
5. 仓库描述与标签：`gh repo edit --description "..." --add-topic ...` 覆盖新能力；
6. `git commit && git push`。

### 6.3 npm 触点

7. 发布（二选一）：
   - **自动（推荐）**：仓库配置 `NPM_TOKEN` secret 后打 tag 触发
     [release workflow](https://github.com/BigBlueBaby/codex2dsh/actions)：
     `git tag v<版本> && git push origin v<版本>` —— workflow 自动跑
     check:fixtures → npm test → L3 冒烟 → `npm publish --provenance` → GitHub Release；
   - **手动**：`npm publish`（需 npm 2FA / access token），注意
     `publishConfig.registry` 已固定为 `registry.npmjs.org`；
8. 验证：`npm view codex2dsh version` 等于新版本；npm 包页 README 自动跟随
   包内 `README.md`（无需单独同步）。

### 6.4 插件市场触点（awesome-dsh-plugin，已收录后）

9. 描述/分类/截图更新走新 PR（只改自己条目）：
   - fork → 更新 `data/plugins/BigBlueBaby__codex2dsh.yml`（`description.en/zh`
     与最新功能一致，只述功能不夸大）；
   - 截图变化时更新 `data/screenshots.json`（GitHub raw https URL）；
   - `npm ci && node scripts/generate-readme.mjs` 重新生成两个 README；
   - 提交 PR（≤3 条），CI 通过后维护者合并，网站自动重建；
10. npm 下载量自动关联（repository 字段已指向本仓库），无需通知市场。

### 6.5 本地 DSH 触点

11. 本地升级：`dsh plugin --profile <激活的profile> add codex2dsh@<新版本>`
    （若已装旧版先 `remove` 再 `add`），重启 DSH；
12. 重启后：设置 → 插件 → Codex 迁移 → **「验证迁移」**，确认
    MCP 已合并进 profile、工具可执行、AGENTS.md 引用成立；
13. 用户可见性抽查：面板新按钮出现、新会话上下文注入全局指令
    （`Instructions from: ~/.dsh/AGENTS.md`）。

### 6.6 发布前自查（快速清单）

- [ ] `npm view codex2dsh version` 已是新版本（npm 触点已更新）
- [ ] `README.md` 功能表/FAQ 与 `CHANGELOG.md` 一致
- [ ] GitHub 仓库描述/topics 覆盖新能力
- [ ] 插件市场 yml 描述与最新功能一致（或已提 PR）
- [ ] 本地 `codex2dsh verify` 全绿，或仅剩用户决策项（如未配置的 MCP 引用）

## 7. 卸载与降级承诺（写入 README）

- 卸载 = 移除 profile 中插件的 insert 行 + `dsh plugin remove codex2dsh`；
- **插件永不自动删除已迁移资产**（技能/指令/镜像片段/台账）；
- 迁移是单向翻译，不提供"自动回滚到 Codex"（源侧从未被修改，回滚 = 继续用 Codex 即可）。

## 8. 发布检查清单（最终 gate）

- [ ] `npm test` 全绿（L1+L2），L3 冒烟通过，L4 演练完成
- [ ] `npm pack --dry-run` 内容正确（含 cordis.patch.yml，无 secrets，无生命周期脚本）
- [ ] 无锁文件泄漏、无真实配置入库
- [ ] README 徽章/安装命令/文档链接正确
- [ ] CHANGELOG 更新、tag 推送
- [ ] npm publish → `dsh plugin add codex2dsh` 在干净环境验证
- [ ] 提交 awesome-dsh-plugin PR 与各聚合渠道
