# 07 · 发布与分享

> 状态：**基线文档**（基于 dshmarket 1.17.1 与 dsh-community-market 契约实测归纳） · 关联：[06-测试与验收](06-测试与验收.md) · [09-安全边界](09-安全边界.md)

目标：让 `codex2dsh` 被"更多人"发现、一键安装、可信。分享链路有四层，按投入产出排序。

## 1. 第一层：npm 发布（一切的基础）

```bash
# 前置：测试全绿（见 06-测试与验收）
npm login
npm version 0.1.0 -m "chore(release): v0.1.0"
git push --follow-tags
npm publish --access public
```

**包体要求**（市场安装器硬性校验，缺一不可）：

- `files` 中必须包含 `cordis.patch.yml` 且文件真实存在、不越界；
- **不得包含** `preinstall/install/postinstall/prepare` 生命周期脚本（市场直接拒绝）；
- 声明与 DSH 兼容的 peerDependencies（`@deepseek-ai/cordis ^4.0.1` 等）与 `engines.node >= 22.13`；
- 提供官方 tarball 与 SHA-512 integrity（npm 自动保证）。

## 2. 第二层：awesome-dsh-plugin.com 注册表收录（人工 PR）

DSH Desktop 内置市场的"发现"视图读取 **awesome-dsh-plugin.com** 的精选清单，条目字段（实测 `RegistryPlugin`）：


收录方式：向 [awesome-dsh-plugin/awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 提交 PR（参考 dsh-chat-import 的收录记录：其 ROADMAP 列出了 8+ 个已收录渠道）。

## 3. 第三层：dsh-community-market 目录（DSH Desktop 市场页）

DSH Desktop 的市场页（Market）按 **catalog-provider-contract v1** 工作：

```
标准来源 manifest（静态 JSON，自述查询能力）
   └─ GET /v1/plugins ──► 标准适配器（standard-http）──► 标准化快照
合作方（1024Store / dshfind）──► 内置适配器（dsh-1024store.ts / dshfind.ts）
```

要点（来自契约文档与实现）：

- **市场无默认/兜底来源**：用户必须显式选择或添加来源；任何人可发布符合契约的来源（manifest URL），不需要合作批准；
- 来源 manifest 决定条目：`package`（npm 名）、`latestVersion`、`repository`、`category`、展示字段；
- **安装只认精确 npm 包**：拒绝 GitHub URL、版本范围、`latest`、prerelease、带生命周期脚本的包；安装前做 `preview`（官方 registry 复核 + 当前 profile 复核），确认后受管 `pnpm add`；
- 安装前 Desktop 对 profile 的 `package.json / pnpm-lock.yaml / pnpm-workspace.yaml` 做快照，失败回滚；重启后健康才提交；
- 因此我们的发布动作：**保证 npm 包质量**（§1 清单）+ 视需要向 1024Store / dshfind 提交收录申请（按其对外的收录流程）。

## 5. 版本管理与 CHANGELOG

- **SemVer**：`0.x` 阶段 minor 兼容破坏需在 README/CHANGELOG 标注；peer 版本策略（`@deepseek-ai/*` rc 系列）跟随生态基线（当前：cordis ^4.0.1 / dsh-tools ^0.1.0-rc.6）；
- **发布流程**：`npm version` 打 tag → push → `npm publish`；`CHANGELOG.md` 按 [Keep a Changelog](https://keepachangelog.com/) 维护，与 docs 状态行同步；
- **CI 门禁**：`prepublishOnly` 跑 `npm test && git diff --quiet && npm pack --dry-run`（参考生态做法），防脏发布。

## 6. 卸载与降级承诺（写入 README）

- 卸载 = 移除 profile 中插件的 insert 行 + `dsh plugin remove codex2dsh`；
- **插件永不自动删除已迁移资产**（技能/指令/镜像片段/台账）；
- 迁移是单向翻译，不提供"自动回滚到 Codex"（源侧从未被修改，回滚 = 继续用 Codex 即可）。

## 7. 发布检查清单（最终 gate）

- [ ] 无锁文件泄漏、无真实配置入库
- [ ] README 徽章/安装命令/文档链接正确
- [ ] CHANGELOG 更新、tag 推送
- [ ] npm publish → `dsh plugin add codex2dsh` 在干净环境验证
- [ ] 提交 awesome-dsh-plugin PR 与各聚合渠道
