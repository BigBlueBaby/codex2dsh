# 01 · 总体架构

> 状态：**基线文档**（v1，随实现同步更新） · 关联：[02-Codex配置解剖](02-Codex配置解剖.md) · [03-映射规范](03-映射规范.md) · [04-插件API参考](04-插件API参考.md)

## 1. 项目目标

`codex2dsh` 是一个 **DeepSeek Harness（DSH）插件**，把 OpenAI Codex CLI / Codex Desktop 的本地资产迁移为 DSH 原生形态：

| 资产类别 | 目标形态 | 一句话说明 |
| --- | --- | --- |
| MCP 服务器 | DSH MCP client 配置片段 | 生成可审阅的 YAML，人工合并，**不自动改 profile** |
| 技能 Skills | DSH 持久化技能资产 | `$DSH_AGENTS_HOME/skills/<name>/SKILL.md` |
| 全局指令 | DSH 指令资产 / preset | `AGENTS.md`、`instructions.md` 适配为 DSH 指令体系 |
| 记忆 | DSH 记忆资产 | 只读导出、可检索 |
| 模型 / Provider | DSH `settings.yaml` 建议 | 只读建议，人工确认后生效 |
| 会话历史 | DSH 可续聊会话 | 委托 `import_chat`（dsh-chat-import） |

**设计原则**（详见 [09-安全边界](09-安全边界.md)）：

1. **源码只读**：绝不改写 `~/.codex/**` 任何文件。
2. **dry-run 优先**：一切写盘操作默认预览，`apply:true` 才落盘。
3. **密钥脱敏**：`password / token / key / secret` 一律掩码为 `****`，建议环境变量化。
4. **人工确认**：涉及 profile 的改动（MCP、模型、权限）只生成建议片段，由用户审阅合并。
5. **幂等可重入**：同一来源重复迁移跳过或增量，不产生垃圾副本。

## 2. 范围界定（与 dsh-chat-import 的关系）

| 能力 | dsh-chat-import（生态既有） | codex2dsh（本项目） |
| --- | --- | --- |
| Codex 会话导入（rollout JSONL → DSH 会话） | ✅ `import_chat` / `scan_discover` | 委托，不重复实现 |
| 通用 agents/skills 导入（pi/opencode/Claude/Codex 混源） | ✅ `import_agents` | 参考其 `kind:dsh` 落盘规范 |
| MCP 通用镜像（Claude/Codex → YAML 片段） | ✅ `import_mcp` | **做 Codex 专项的完整字段级镜像**（env 展开、`startup_timeout_sec`、http/sse 类型、密钥策略） |
| 配置建议（Claude settings / Codex config） | ✅ `import_settings` | **做 Codex 专项的迁移执行**（不只是建议，还有落盘目标与台账） |
| 记忆迁移 | ❌ 无 | ✅ `migrate_codex_memory` |
| 迁移台账 / 体检 | 部分（`doctor`） | ✅ `codex2dsh_doctor` + 迁移台账 |

**协同方式**：`codex2dsh` 声明对 dsh-chat-import 的**可选协同**（不强依赖）：会话迁移工具在检测到 `import_chat` 工具存在时直接委托，否则给出安装指引。

## 3. DSH 插件体系（本项目立足的运行时）

> 以下为对 DSH 0.1.x 生态（本机 `0.1.1-rc.2` 实测）的架构归纳，是开发本项目必须理解的地基。

### 3.1 运行时分层

```
┌─────────────────────────────────────────────────────┐
│ DSH Desktop（Electron 壳，dsh-plugin-desktop）       │
│   ├─ web 客户端（dsh-web-app 组合）                   │
│   └─ 桌面服务：terminal / profiles / updates / pnpm   │
├─────────────────────────────────────────────────────┤
│ DSH 核心（@deepseek-ai/dsh-base + Cordis 运行时）     │
│   ├─ host 服务：sessionPersistence / fs / tools /    │
│   │              workspaceRegistry / webServer ...   │
│   └─ 插件层：Cordis 组合（bundle 堆叠 + patch 覆盖）   │
├─────────────────────────────────────────────────────┤
│ 用户数据根：$DSH_HOME（默认 ~/.dsh）                  │
│   ├─ profiles/<name>/   profile 组合（见 3.3）        │
│   ├─ sessions/          会话日志                      │
│   ├─ settings.yaml      agent-default-model / 权限等  │
│   └─ dsh-chat-import/   生态插件数据（imports registry 等）│
└─────────────────────────────────────────────────────┘
```

### 3.2 插件 = npm 包 + Cordis 组合条目

一个 DSH 插件就是一个 npm 包，包内通过 `package.json` 的 `dsh` 字段声明组合方式：

```jsonc
{
  "name": "codex2dsh",
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },   // 组合补丁：把本插件插入 profile 层栈
    "client": {
      "inject": ["@deepseek-ai/dsh-client-locale"], // 需要注入的 web 客户端包（可选）
      "platform": "web"
    }
  },
  "peerDependencies": {
    "@deepseek-ai/cordis": "^4.0.1",               // 插件框架（koishi 系）
    "@deepseek-ai/dsh-tools": "^0.1.0-rc.6",       // 工具注册 API（defineTool）
    "@deepseek-ai/schemastery": ">=3.0.0"          // 参数 schema
  }
}
```

`cordis.patch.yml` 内容（把插件插入 profile 的层栈）：

```yaml
- insert:
    - id: codex2dsh
      name: codex2dsh
```

### 3.3 Profile（插件组合单元）

`~/.dsh/profiles/<name>/`（如 `desktop`、`web`）是独立组合单元：

- `package.json` —— `dsh.profile.bundles` 声明启用哪些 bundle（如 `["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-chat-import"]`）；`dependencies` 声明插件包版本；
- `cordis.yml` / `cordis.patch.yml` —— 组合补丁层（用户可手工追加 `- insert:` 条目）；
- `node_modules/`、`pnpm-lock.yaml`、`pnpm-workspace.yaml` —— 由 `dsh plugin` 管理。

**安装命令**（dsh CLI 实测可用）：

```bash
dsh plugin --profile web add <npm-package>          # 装 npm 包
dsh plugin --profile web add -w link:/path/to/pkg   # 本地开发（符号链接，改代码即生效）
```

> 卸载 = 从 profile 的 bundles / 补丁移除该插件的 insert 行并重启；**插件永不自动删除已迁移数据**。

### 3.4 host 服务（插件消费面）

插件入口 `apply(ctx)` 拿到 Cordis 上下文，可注入（`inject`）并消费以下 host 服务：

| 服务 | 用途（本项目） |
| --- | --- |
| `fs` | 读写 `$DSH_HOME` 下的台账 / 镜像产物（只读 Codex 源） |
| `tools` | `ctx.tools.register(defineTool({...}))` 注册迁移工具 |
| `sessionPersistence` | 会话相关操作（委托场景） |
| `workspaceRegistry` | 按 cwd 归组（委托场景） |
| `webServer`（可选） | 面板路由（`/codex2dsh/*`），headless 下不挂载 |
| `commands`（可选） | `/codex2dsh` 等斜杠命令 |
| `settings`（可选） | 插件配置命名空间（如导入系统提示开关） |

## 4. 技术栈决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 语言/模块 | 纯 ESM JavaScript（`.mjs`） | 与参考插件 dsh-chat-import 一致（零构建链、`type: module`、Node ≥ 22.13），DSH 生态内发布最简路径 |
| 插件框架 | `@deepseek-ai/cordis`（peer） | DSH 运行时标准 |
| 工具注册 | `@deepseek-ai/dsh-tools` 的 `defineTool` | host 标准 API，工具面与 dsh-chat-import 对齐 |
| TOML 解析 | 自研轻量解析（`lib/config.mjs`） | 只解析我们关心的节（`mcp_servers` / `model_providers` / `projects` / `memories` / `features` / `plugins`），避免引入重依赖；复杂语法（多行数组等）降级为"需人工确认"并明示 |
| YAML 生成 | 自研缩进渲染（`lib/yaml.mjs`） | MCP 镜像片段格式简单，不引依赖；生成结果以 fixture 单测锁定 |
| 测试 | Node 内置 `node:test` + `assert` | 零依赖、CI 友好；沿用生态惯例（dsh-chat-import 同款） |
| 密钥处理 | 掩码 `****` + 环境变量占位建议 | 见 [09-安全边界](09-安全边界.md) |

## 6. 关键非目标（Non-Goals）

- ❌ 不迁移 **凭据**（`auth.json`、`.codex-global-state.json` 中的 token/refresh_token、浏览器 cookie）。
- ❌ 不迁移 **桌面主题/外观**（`[desktop]` 主题色、字体）——与 DSH 皮肤体系不通用，明示跳过。
- ❌ 不**自动**修改任何 profile 的 `cordis.patch.yml` / `settings.yaml`——只产出建议与镜像片段。
- ❌ 不实现 Codex 会话导入——委托 dsh-chat-import。
- ❌ 不打包 Codex 的 marketplace 插件本体（`[plugins.*]`、`openai-bundled` 等）——其许可证与运行时绑定 Codex 分发，仅做"存在性报告"。
